Fix rA|0 rule for vector indexed loads/stores (lvx/stvx) - 2364 sites

For X-form indexed ops, rA field == 0 means the LITERAL value 0, not gpr[0]
(r0 can never be a base register). The lifter emitted the lvx/stvx effective
address as (gpr[rA] + gpr[rB]) & ~0xF and, when rA==0, wrongly added gpr[0].
Latent while r0==0 (its common scratch/zero value) but corrupts the address when
r0 holds a value: func_00017ED4 does `addi r0,r1,0x290` then `stvx v31,0,r0`, and
the buggy (gpr[0]+gpr[0]) doubled sp+0x290 (~0xDFFFF9C0) to 0xBFFFF380 -> AV in
the C++ unwind path.

Fix via _apply_vecra0.py: drop the bogus gpr[0] addend so EA = gpr[rB] & ~0xF.
Only the lvx/stvx EA pattern (`& ~0xFULL`) is matched; ordinary loads and
non-zero-rA forms are untouched. Baseline-safe: 221102 lines, all threads
finished (2 runs).

With this + the fcmp (d85bb7b) and formatter-stfd (10b2d38) fixes,
GAMEWORLD_REAL_INIT advances past the 0xBFFFF380 AV to a new one (vm_write32 to
0x12F01FC4 in func_000174DC, sign-extended SP again - next target).
