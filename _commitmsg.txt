Bump-allocator LIFO reclaim - clears 0x12F01FC4 overflow AV

The game has a "probe the largest allocatable size" loop (loc_0003A984): it
calls func_000D9128(size) starting at 0x9400000 (148 MB) and, only if the
allocator returns 0, reduces by 1024 and retries; on success it frees the test
block (func_000D90FC) and does the real allocation. The loop relies on the
allocator FAILING when a size won't fit.

Our uninitialized-slab fallback bump allocator always succeeds, so the probe
"succeeds" at 148 MB; the test block was never reclaimed (bump free was a no-op),
so the subsequent real 148 MB allocation started at 0x9B02000 and its region
extended to 0x12F02000 - past the committed ceiling 0x10010000 -> AV writing
0x12F01FC4 in func_000174DC.

Fix: give the bump allocator LIFO reclaim. func_000D9128 records the start of the
last allocation; func_000D9108's uninit-slab free path rolls the bump pointer back
when the most-recent block is freed. Now the probe's free reclaims the space and
the real allocation reuses 0x702000, so the single 148 MB region fits within
committed RAM. Verified: both allocs land at 0x702000, no AV.

Baseline-safe: 221102 lines, identical SLAB-BUMP/SKIP counts (1/1), all threads
finished. GAMEWORLD_REAL_INIT now advances past the AV (busy in the menu-tree
build / observer-dispatch phase; no AV, no read-spin in 45s).
