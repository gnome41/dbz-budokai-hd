Skip null-slab free in func_000D9108 - clears Terminate-Thread abort

After the SPURS +0x18 guards, the GAMEWORLD path advanced into the Terminate
Thread cleanup, which freed the bump-slab block 0x701000 with slab_base==0 (the
TOC[-0x603C] slab pointer was null on this path). The SLAB-SKIP guard only fired
for `slab_base != 0 && slab+0x10==0`, so a null slab fell through to the real
free func_000D5FD0 -> block-header abort (func_000D91E4, syscall 988 r3=4).

Fix: skip the free when the slab is unusable - either slab_base==0 (null) OR
slab+0x10==0 (uninitialized pool). In both cases the block came from our bump
fallback (no slab header), so the real free would abort. Condition changed from
`slab_base != 0 && ...` to `slab_base == 0 || ...`.

Baseline-safe: 221102 lines, all threads finished (a null-slab free never occurs
in the default build, so this is inert there).

RESULT: GAMEWORLD no longer aborts and runs far past the baseline - the SPURS/SPU
render subsystem runs heavily (sphere/EDGE; ~220k SPU-interp lines), 19 threads,
no AV/abort/hang. The menu event cycle is still not reached: the orchestration
threads (Initialize/Regist Context/Unlock) are registered but not yet spawned, no
sys_event_queue_create, no cellSpursAddWorkload - the original event-cycle wall.
