Event-cycle Phase C: force-spawn + run the orchestration threads

With the game-world init complete, the orchestration threads
(Initialize/Regist Context) are registered but their spawn (thread-manager
vtable slots func_000317EC/00031850) is only triggered by the event-driven menu
startup we don't reach. Two parts:

1. Force-spawn (GAMEWORLD-gated, in func_00024DE0 after init): capture the
   thread-manager `this` in its ctor func_00031548 (g_thread_mgr) and invoke
   func_000317EC/00031850 directly (each with a manual 0x70 stwu for its
   dropped prologue). This creates "Initialize Thread"(0x31364) and
   "Regist Context Thread"(0x313AC) via sys_ppu_thread_create.

2. Off-by-4 entry wrappers (extra_funcs.cpp + extra_table): the thread entry
   OPDs point at 0x31364 / 0x313AC whose leading stwu was dropped; bodies are
   func_00031368 (sp+=0x70) and func_000313B0 (LR@sp+0x90, frame 0x80). Without
   them the thread proc logged "UNRESOLVED entry" and stubbed the threads.

RESULT: both orchestration threads now resolve and RUN to clean exit (no AV) -
they execute func_00031368/func_000313B0 which call func_000F151C / func_000F14BC
/ func_000F20DC (sysPrxForUser sync/event). NEXT LAYER: those event functions are
stubbed, so no event queue is created yet (0 sys_event_queue_create). Making them
create real queues/handlers is the remaining event-cycle work (Phase D).
